# ContactsExplorer - iOS Home Assignment

Welcome! Before you write any code, read this. It is short.

## The story

Congratulations, you just inherited a codebase.

ContactsExplorer was written by a junior developer on our team. They shipped a working app and learned a lot doing it, but as juniors do, they made some mistakes along the way. Some things are subtly broken. Some things work but might make you frown. And some things are perfectly fine as they are.

The developer has moved on. The project is yours now.

## Your task

Make this project your own. Treat it exactly like a real codebase you just took ownership of:

- Explore it. Run the app, use it, read the code (tests included).
- Fix what is broken.
- Change whatever bothers you: rewrite, restructure, rename, delete. You can even redesign the UI.
- Leave alone whatever you think is fine. Not everything needs to change, and telling the difference is part of the job.

There is no checklist and no official bug count to hunt down. When you are done, the project should feel like home: a codebase you would be happy to keep building on, and happy to defend in a code review.

## What the app does

A small SwiftUI app around the device's contacts:

- Shows the contacts in a scrolling list, after asking for permission
- Filters the list as you type a name or a phone number
- Tapping a contact opens a detail page (photo, phone numbers, emails, and so on)
- Contacts can be marked as favorites from both the list and the detail page, and the favorite state persists

This behavior should still exist when you are done. Everything else - how it looks, how it is built, how it is organized - is your call.

## Ground rules

- **Time: up to 4 hours total.** Please stop there. You will probably not get to everything, and that is expected. Prioritizing is part of the assignment.
- **AI is encouraged.** Use whatever tools you like, however you like. The one condition: you own the result. Every line of the final project, whoever typed it, is one you can explain.
- **No third-party frameworks are required.** Add one only if you feel it earns its place.

## Getting started

1. Open `ContactsExplorer.xcodeproj` in a recent Xcode and run it on a simulator. The simulator's address book already has a few sample contacts; add more if you want richer data.
2. Spend a few minutes using the app like a user would.
3. Then read the code like a reviewer would.

## What we look for

- **Judgment**: what you chose to fix first, what you deliberately left alone, and the reasons behind both.
- **Craft**: the code you write, and the code you keep, both carry your name now.
- **Ownership**: you understand every change in the project you hand back. You drive the AI, not the other way around.

## What happens next

We review the project first. It stands on its own, and it decides whether we move forward. Either way, we will send you feedback on your submission.

If we move forward, the next step is a conversation about your project. We will open it together, point at changes you made, and ask why. We might point at things you left untouched and ask about those too. There are no trick questions and no single right answer, but "that is what the AI generated" is not a why. This should be your project by then, and you should know it like you wrote it.

Have fun with it. Good luck!
